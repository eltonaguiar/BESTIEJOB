## Lessons for future agents

1. Adzuna demo key rate-limits fast: HTTP 429/503 after ~4 rapid queries (9 of 12 failed in one earlier round at 0.5s spacing). Space calls ≥3s; surviving queries still return rows the hourly scan already ingested. Do not treat 429/503 as "empty board".
2. LinkedIn guest: HTTP 200 is not proof of cards — the authwall returns status=200 with the same md5 (~337 KB). Healthy card HTML is ~31 KB and differs per query; test length + digest distinctness, never `len()` alone. `f_TPR=r3600` is near-empty pre-dawn EST; use `r86400` and let the ATS sweep carry hourly freshness.
3. Workday CXS IS reachable from this host: use `wdN` host + `curl --compressed` (bare tenant host is NXDOMAIN; without `--compressed` the gzipped body decodes to nothing). Verified pairs: `bmo.wd3/External`, `td.wd3/TD_Bank_Careers`, `cibc.wd3/search`, `salesforce.wd12/External_Career_Site`, `caatpension.wd10/Careers`, `gdit.wd5/External_Career_Site`. Guessed tenants (capgemini, kyndryl, ibm, cgi, cognizant, telus, rogers, kpmg, scotiabank, intact, loblaw, cprail) = 422; `rbc/pwc/sunlife` = 404.
4. `daily_job_scan.mjs` rewrites jobs.json from scratch each hour and carries existing rows (pruning only invalid/stale/>45-day/generic). Never re-test carried rows against tag keywords — that deleted 230 in-remit rows on 2026-11-04.
5. Dedup: normalize URL (strip query/trailing slash); LinkedIn job-id equality is a hard dedupe signal even when titles differ; vendor twins (different staffing firms, same client req) are distinct — dedupe on URL only.
6. `scripts/sync_readme_to_jobs.mjs` is a silent no-op on the current README (tables are one-line mangled blocks). Write to jobs.json directly, rebuild with `tools/build_site.py`, and treat README main tables as display-only; the `<!-- DAILY-SCAN:START -->` block is the only auto-refreshed README slice.
7. `git push` to main is constantly raced by peer agents: push → on rejection `git pull --rebase --autostash origin main`, resolve generated files with `git checkout --theirs` (latest scan wins), continue, push. Do not `git push --force`; the last hourly scan on origin/main (22:11Z, 2677 listings) was superseded by this run's (22:07Z, 2728 listings) and replaced on main.
