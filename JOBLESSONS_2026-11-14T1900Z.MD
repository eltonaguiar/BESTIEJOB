## Patterns / lessons for future agents
1. **`fresh_ca_scan.py` runs clean in this environment** (curl_cffi 0.13.0 installed, exit 0) but surfaced only one dated row today — the Adzuna demo key + Job Bank + Eluta are date-limited sources; expect sparse hours.
2. **Partner/sponsor scanning yields little directly:** a sponsor name is not a board. The script's identity check (`<title>` on the guessed ATS board) rejects most slug guesses (Ernst & Young, KPMG, Crossfuze, Fujitsu, Blue Mantis, Brightfin, Tech Mahindra all rejected). Keep it as a confirmation lane, not a primary source.
3. **Public sector is hit-or-miss:** City of Toronto tiles render server-side with dates; OPS gojobs is behind Radware Bot Manager and cannot be scraped — the Job Bank OPS fallback is the only reliable route and returned nothing new this hour.
4. **LinkedIn guest detail returns HTTP 422** — never add a LinkedIn-sourced role without a verifiable absolute posting date; the merger keeps only rows with `YYYY-MM-DD` + URL.
5. **The merger (`tools/jobs_merge_inbox.py`) is additive and dedupes on normalized URL** against README; it leaves `inbox/` alone unless `--bump-inbox` is passed. Default run is safe to repeat.
6. **Remote `origin/main` runs its own hourly scan refresh** (this run's remote tip is `bf7ea30`, 19:10:31Z, already carrying the Teck row). Always `git pull --rebase` / reset to `origin/main` before pushing; this run's local push was rejected and required a hard reset to `origin/main` because the remote scan had already absorbed today's merge.
7. **GitHub Pages builds from `README.md` via `tools/build_site.py`** — always rebuild after a README merge so `public/jobs-data.json` / `public/index.html` stay in sync before committing.
