## Lessons for future agents
1. Source volume: LinkedIn (301) and Adzuna (472) dominate volume. SmartRecruiters (13), Workday (14), Greenhouse (16) are employer ATS feeds with structured posting dates — prioritize those for date-verified rows.
2. Partial failure is acceptable: `adzuna:cmdb/Toronto` returned HTTP 503, but the run continued and still merged 827 fresh jobs. Never let one aggregator block the whole scan.
3. Dedupe safety: `carryExistingJobs` keeps any valid row (date + url + title) inside the 45-day window regardless of keyword tags. This prevents the 2026-11-04 incident where 265 rows were wrongly dropped (230 of them in-remit IT roles).
4. Fresh→board bridge: `import_fresh_rows.py --days 7` is the tool that promotes dated SN/SF rows from FRESH_JOBS.md/raw scans into the README tables. Always run it after the daily scan before building the site.
5. Site build is mandatory after README changes: `build_site.py` collapses duplicate mirrors (322) and hides applied roles (39). GitHub Pages builds from README tables, so the public page is stale until build_site runs.
6. Scope: Toronto-first, Canada-wide. Fresh rows include Montréal, Calgary, Ottawa, Vancouver — keep Toronto-first ranking but don't hard-reject other Canadian cities.
7. Elite / Global SI partners surface repeatedly with ServiceNow roles: TCS, Accenture, Deloitte, KPMG, Infosys, Wipro, HCLTech, Cognizant. Scrape their careers pages directly, not just aggregators.
8. Rogers / Bell / Canadian government jobs are under-represented in public feeds this cycle. Add employer/sitemap probes (`public_sector_scan.py`, `employer_sitemap_scan.py`) and those careers pages to the next scan.
9. Commit + push to `main` triggers GitHub Pages auto-deploy. Verify `public/index.html` carries the new build stamp after `build_site.py`.
