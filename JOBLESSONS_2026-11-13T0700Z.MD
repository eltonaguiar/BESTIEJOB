## Lessons for future agents

1. **Check `origin/main` before pushing.** A peer hourly Action can land between your scan and your push; pushing a duplicate refresh creates conflicts. If remote already holds an equivalent refreshed board (same listing count, today-dated rows present), reset local to origin and record a null/net-zero run rather than force-pushing.
2. **A null/net-zero hourly run is normal, not a failure.** The board is already dense (~2610 feed / ~5090 page cards); most fresh surfacings are mirror re-listings already deduped by URL.
3. **Pipeline is verified end-to-end locally:** daily_job_scan → import_fresh_rows → sync_readme_to_jobs → build_site all execute and the page reflects today's date. The GitHub Action holds the Adzuna/LinkedIn secrets and is the authoritative full sweep; local runs are a supplement.
4. **Don't manufacture rows to "hit a number."** import_fresh_rows reported 30 new locally, but origin's equivalent scan already captured the same fresh requisitions (GDIT, PwC, IKO). Dedup by URL + company/title fingerprint before counting anything as new.
5. **Partner portals (PwC, Deloitte, Accenture, CGI, KPMG) and Workday ATS (BMO, CAAT Pension, GDIT, IKO) are the freshest SN/SF source;** Job Bank and generic web search mostly return expired/410/login-walled postings.
