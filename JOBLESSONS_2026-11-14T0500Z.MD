## New technical lessons (durable)

1. **Workday CXS works from this host — you must use the `wdN` host AND `curl --compressed`.**
   `bmo.myworkdayjobs.com` is NXDOMAIN (verified via DoH: Status 3); the real host is
   `bmo.wd3.myworkdayjobs.com`. Requests to the bare tenant host return HTTP 000. Earlier runs
   concluded "curl is blocked / empty body" because `-o file` without `--compressed` writes the
   gzipped payload (3–7 KB that looks empty when catted). With `--compressed` plus
   `Origin`/`Referer` headers, POSTs return full JSON (`total`, `jobPostings[].postedOn`).
   This is now the cheapest hourly freshness oracle for employer-direct reqs.

2. **Verified Workday tenant/site pairs (POST 200 with JSON):** `bmo.wd3/External`,
   `td.wd3/TD_Bank_Careers`, `manulife.wd3/MFCJH_Jobs`, `interac.wd3/interac`,
   `cibc.wd3/search`, `caatpension.wd10/Careers`, `iko.wd3/IKO_Careers`,
   `accenture.wd103/AccentureCareers`, `salesforce.wd12/External_Career_Site`.
   Newly probed and rejected: `canadalife.wd3`, `telus.wd3`, `desjardins.wd3`, `loblaw.wd3`,
   `kpmg.wd3`, `deloitte.wd3`, `cgi.wd3` → 422 (wrong site name); `sunlife.wd3`, `rbc.wd3` → 404;
   `dxctechnology.wd1/dxcjobs` and `cognizant.wd1` → 521 (Cloudflare). Do not retry these blind.

3. **Accenture CXS is global and relevance-sorted — always append the city to `searchText`.**
   `searchText:"ServiceNow"` returns 1,631 reqs page 1 from Manila/Madrid/Prague. Use
   `"ServiceNow Toronto"` / `"Salesforce Toronto"`; that returned 4 / 18 Toronto rows with
   `Posted Today` labels and real `externalPath` links.

4. **LinkedIn `/jobs/search` page 2 (`start=25`) serves the same top cards as page 1.**
   The guest search is relevance-sorted and re-serves the same 60-card block; there is no
   "what the next run finds new" hidden on page 2. Stop spending a navigation on it.

5. **Adzuna API 503s after ~4 rapid queries.** 9 of 12 queries failed at 0.5 s spacing this hour.
   Space calls ≥3 s or accept partial coverage; the successful queries still return the same
   top-of-date rows the hourly scan already ingested.

6. **`scripts/sync_readme_to_jobs.mjs` now parses README rows=0.** The README tables are
   single-line mangled blocks (heading + `<summary>` + separator + several rows concatenated),
   so the sync script's row regex matches nothing and silently no-ops (`readme rows=0 …
   total=2636`). README→jobs propagation is effectively dead; **add new rows to `jobs.json`
   directly** and treat README as display-only. Re-check the script before relying on it.

7. **`tools/build_site.py` classifies this EA role as `family: other` even when it lives in the
   ServiceNow README table.** That is fine — it is tagged servicenow/cmdb/itam in `jobs.json`
   and the site's search still matches. Do not force the family by editing public files.
