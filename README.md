## User / AI agent guide

<details><summary><strong>If you are a person job-hunting</strong></summary>

Open the table that matches the platform you work on. Every row links straight to the
posting, and `Posted` is the date the source published it — not a board's "days ago" label.
Rows are newest first, so whatever sits at the top of a table is the freshest. Aggregator
mirrors (Adzuna, LinkedIn, Talent.com) can lag or expire without notice: open the link
before applying. If a row says `date relative — unverified`, treat the date as a hint only.

</details>

<details><summary><strong>If you are an AI agent adding jobs</strong></summary>

1. **Never edit the three tables directly.** Concurrent agents will collide on them.
2. Drop a file in `inbox/` named `<model-slug>--<YYYY-MM-DD>--v<N>.md`.
3. One row per job, with an **absolute** `YYYY-MM-DD` date and a URL:

```markdown
| Posted | Role | Company | Location | URL |
|---|---|---|---|---|
| 2026-11-02 | ServiceNow Developer | Acme Corp | Toronto, ON | https://example.com/job/1 |
```

4. Same model, same day, more rows? Rename `v1` → `v2` and edit that file. Do not open a second one.
5. Run `python3 tools/jobs_merge_inbox.py --dry-run`, then without the flag.
6. Or open a PR that touches **only** your `inbox/` file.

</details>

<details><summary><strong>Rules the merger enforces</strong></summary>

| Rule | Behaviour |
|---|---|
| Absolute date only | `2 days ago`, `New!` or a blank cell is rejected |
| URL required | rows without `http(s)://` are rejected |
| Duplicate URL | skipped, counted, never re-added (query strings and `utm_*` ignored) |
| Older than 30 days | moved to `README.BAK_*.md`, not into the tables |
| Table size | newest first; everything inside the 30-day window stays visible |

</details>

<details><summary><strong>Troubleshooting</strong></summary>

- `inbox/ is empty` — your file does not match `<model>--<YYYY-MM-DD>--v<N>.md`.
- Row missing after a merge — it was a duplicate URL or it failed the date rule; the merge report says which.
- Scanner block reappeared — `scripts/daily_job_scan.mjs` must be run with `--no-readme` (the workflow already does).

</details>

## How to add jobs to this file

Do **not** hand-edit the three tables above. Drop a submission file in `inbox/` and run the
merger, or open a PR that only touches `inbox/`. Full rules, file naming, dedupe and version
bumping are in [`docs/JOB_SUBMISSION_METHODOLOGY.md`](docs/JOB_SUBMISSION_METHODOLOGY.md).

```bash
python3 tools/jobs_merge_inbox.py --dry-run   # preview
python3 tools/jobs_merge_inbox.py            # merge + archive expired rows
```

Every row must carry an absolute `Posted` date and a URL that resolves. Relative ages
("2 days ago") are rejected — the merger refuses rows without a `YYYY-MM-DD` date.

## Archive

`README.BAK_2026-11-02T152637Z.md` holds the rows that aged out of the 30-day window on 2026-11-02.
