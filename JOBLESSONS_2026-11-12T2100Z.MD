## Patterns / lessons for future agents
- **Dedupe by company + title (+ city), never URL alone.** Same requisition arrives under LinkedIn/Workday/Adzuna/employer-ATS/dice URLs (BMO workday + LinkedIn twins; Cognizant careers + LinkedIn twin; Pacer jobs.ca + LinkedIn twin; Spectraforce LinkedIn + dice). Same staffing firm + same role + same city = one row; skip the second URL rather than double-listing. CloudLabs also advertises one Architect requisition under multiple cities (Toronto / Quebec City / Calgary on talent.com) — vendor twins are distinct rows and both stay when URLs differ.
- **Never invent a posted date.** Undated Workday rows carry an em-dash `Posted`; skipped, never assigned an invented date.
- **Title rule is a hard filter.** Rogers Lead Management Operations (Salesforce marketing ops) and ServiceNow's own CRM sales roles are excluded despite mentioning the platform.
- **Always check the canonical employer page before counting a role live.** Bell's ServiceNow Dev looked fresh on aggregators; canonical page returned HTTP 410 "filled" — verified closed.
- **Adzuna detail pages 500 via keyless extractors** (Firecrawl all engines failed on adzuna.ca/details/5961946308). Trust the dated sweep file for title/company/location/date, then diff the URL set against the board before adding.
- **`scripts/sync_readme_to_jobs.mjs` readme parser is fragile:** heading suffixes like `(1193)_developer / administrator ...` break family detection (name no longer matches SECTIONS keys), and `|||`-prefixed rows shift the date cell out of body[0]. As a result sync added 0 readme rows this run; new curated README rows must be added to jobs.json by hand (endorsed by the repo procedure) to keep the feed complete.
- **talent.com served mismatched content** for the CloudLabs adzuna id (returned an AGF Management role instead) — do not treat talent.com detail URLs as reliable verification; rely on the dated sweep + search snippet instead.
