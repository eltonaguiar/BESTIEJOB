## Patterns worth reusing

1. **18:00 EST is a low-yield slot**, like 17:00 EST: 0 net-new across three scanners. Highest-yield windows remain 07:00–10:00 and 13:00–15:00 EST. Don't read a 0-new hourly result as a broken scanner.
2. **Check the feed is a superset first.** `node scripts/sync_readme_to_jobs.mjs --dry-run` printing `added=0` is the fastest proof the board is current before declaring "nothing new".
3. **`gap_scan --adzuna` "+N new" can be a sync artifact, not a posting.** It compares against `jobs.json`; a row already in README but normalized differently in the feed (`5970077372` TD Sr Solution Architect) counts as "new". Always grep the URL in README before calling it fresh — and revert the feed churn if it's a duplicate.
4. **`daily_job_scan.mjs` requires stdout to be a pipe/TTY** on this Windows host — `> file` redirection makes it exit `stdout is not a tty` immediately with no writes. Run it in the foreground piped (`… 2>&1 | cat > log`), not with a bare file redirect, when a local breadth scan is actually needed.
5. **CI `[skip ci]` commits don't trigger pages.yml.** Data refreshes deploy on the pages.yml `:35` cron; to publish immediately after a local push, `gh workflow run pages.yml -R eltonaguiar/BESTIEJOB`.
6. **`gh` needs `-R`/`GH_REPO` on this host** — it otherwise tries the blocked `mingw64/bin/git.exe` and dies with "Access is denied".
