## Technique notes (reusable next cycle)

1. **LinkedIn guest API works via curl.** `curl --compressed` with `User-Agent` (Chrome/125) + `Accept-Language: en-CA,en;q=0.9` on `https://www.linkedin.com/jobs-guest/jobs/api/seeMoreJobPostings/search?keywords=<q>&location=Toronto,%20Ontario,%20Canada&f_TPR=r86400&start=0` returns real card HTML (compressed body ~18–25 KB with `data-entity-urn="urn:li:jobPosting:<id>"`, `datetime="YYYY-MM-DD"`, absolute `href`). A compressed body under ~2 KB means empty/near-empty — treat as zero results, not an error. Sleep ~26 s between queries; 4 back-to-back calls risk HTTP 429 on an authwall-shaped 200 response.
2. **Parse from `data-entity-urn`**, not from `<li>` (the `job-search-card` class lives on an inner div). Strip `?position=...&pageNum=...&refId=...&trackingId=...` from the card href for the canonical URL.
3. **LinkedIn job-id equality is a hard dedupe signal** — e.g. "Salesforce Administrator / Application Support Specialist (Intermediate)-5816" and "Intermediate Salesforce System Coordinator-5816" share one job id. Compare the trailing numeric id before adding.
4. **Workday `postedOn: "Posted Today"` is not a Canada signal** — Sunlife posted ServiceNow/Architect roles in Gurugram and Bangalore on "Posted Today". Always read the `/job/<City>/…` slug and country before counting a fresh hit.
5. This host cannot run `curl` from Python subprocess (WinError 5) — drive probes from bash directly. `gh` shells out to bundled git and fails the same way; use git directly in the terminal tool.
6. Salesforce targeting priority: exact titles "Salesforce Platform Administrator" / "Platform Developer I" (entry-level 0–2 yrs) first; generic "Salesforce Developer" and Salesforce-flavored titles (nCino, Revenue Cloud, Data Cloud, CPQ) are secondary but still board-eligible if dated and Canada-located.
