## Techniques that paid off

1. **Workday CXS search API is the best freshness oracle for Canadian employers.** POST
   `https://{tenant}.wd{1,3}.myworkdayjobs.com/wday/cxs/{tenant}/{site}/jobs` with
   `{"appliedFacets":{},"limit":20,"offset":0,"searchText":"ServiceNow"}` returns `postedOn`
   ("Posted Today" / "Posted 2 Days Ago") per requisition. Confirmed working: `td/TD_Bank_Careers`,
   `bmo/External`, `dxctechnology/dxcjobs`, `accenture.wd103/AccentureCareers`,
   `salesforce.wd12/External_Career_Site`, `huron.wd1`, `interac.wd3`.
   Every wrong `{site}` guess returns **HTTP 422** — treat 422 as "wrong site name", not as no jobs.
2. **Per-job absolute date**: GET `.../wday/cxs/{tenant}/{site}/job/{externalPath}` →
   `jobPostingInfo.{postedOn,startDate,endDate}`. `startDate` is the authoritative ISO date
   (`2026-11-09`) even when `postedOn` is relative. `endDate` gives the application deadline.
3. **LinkedIn guest API works if you call it same-origin from inside the browser.** Load any
   `https://www.linkedin.com/jobs-guest/jobs/api/seeMoreJobPostings/search?...` URL first, then
   `fetch('/jobs-guest/...')` from that page — no CORS problem, HTTP 200, full card HTML
   (title / company / location / `datetime` / absolute `Posted` date). Plain `requests` and
   `curl_cffi` are not interchangeable here: **curl_cffi is NOT installed in this host's Python and
   `pip` is missing from the Hermes venv**, so do not plan on the repo's `linkedin_guest_scan.py`.
4. **Rate limit is roughly 4 rapid guest searches, then HTTP 429.** Batch 4 queries, wait ~25 s,
   batch 4 more. 429 responses still return 24 KB of HTML — check `status`, never parse on `len()`.
5. **LinkedIn detail pages ARE readable as a guest in the browser** (`new_tab()` + `innerText`).
   `web_extract` on the same URL times out (CRAWL_LIVECRAWL_TIMEOUT). Use the browser when you need
   the description text to prove "ServiceNow" or "Salesforce" is actually in the body.
6. **`scripts/ats_board_sweep.py --days 2` is the cheapest wide net**: 455 employer boards
   (Workday/Greenhouse/Lever/Ashby/SmartRecruiters/Workable/Gem/Breezy) → 29.5k raw rows →
   846 keyword-relevant → 79 Canadian → 4 within 2 days → 3 already on board → 1 new (the DXC row).
   Runtime ~4 minutes. Run it every hour; it is the source of most genuine "only on employer site" finds.
7. **builtin.com date markers still cut both ways**: `site:builtin.com/job <kw>` snippets showed
   "Sorry, this job was removed at …" for BMO's ServiceNow Developer (10776183) — hard exclude,
   even though the page renders a full description. Their listing pages use JS-rendered cards, so
   regex on the HTML returns 0 cards; use `site:` search snippets, not the listing page.

## Dead ends worth remembering

- **jobs.gc.ca / Job Bank full-text search is noise**: `searchstring=servicenow` on jobbank.gc.ca
  returns "shipping coordinator", "engineer in agronomy", "account executive". Job Bank matches the
  body text of unrelated NOC postings. Only trust a hit when the *title* is platform-specific.
- **TD single-job CXS endpoint returns 403** even when the search endpoint works. Take dates from
  the search payload; do not GET the single job URL on `td.wd3`.
- **Scotiabank / Rogers / Bell / TELUS / CIBC are not on `wd3` with the obvious site names**
  (`scotiacareers`, `RBC`, `Rogers`, `Bell`, `TELUS`, `CIBC` → 422/404/500). Scotiabank's
  `jobs.scotiabank.com/search/?q=servicenow&sortColumn=referencedate` HTML *is* scrapable and gives
  absolute dates (Nov 9 CIAM roles, Nov 3 Bogota ServiceNow Developer) — use that Phenom search
  instead of guessing Workday paths.
- **EQ Bank / TTEC Digital Lever postings can vanish between searches.** `jobs.lever.co/<slug>/<uuid>`
  returns a page for a closed req, but `api.lever.co/v0/postings/<slug>?mode=json` no longer lists it.
  Always cross-check the UUID against the board's JSON before adding (killed EQ Bank
  "ServiceNow Engineer" 2063ba13 and TTEC "ServiceNow Project Manager" 6e8c92be this run).
